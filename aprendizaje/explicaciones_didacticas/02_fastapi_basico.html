FastAPI desde cero: la misma API en la mitad de líneas

Cómo se instala FastAPI, cómo se arranca el servidor, cómo se declaran rutas y parámetros y qué hace FastAPI por su cuenta con cada petición.

1. Problema

El servidor de la etapa 01 funciona, pero ocupa 189 líneas para tres rutas. La mayor parte de ese código no tiene nada que ver con Punto Lácteo: separa rutas con expresiones regulares, lee el cuerpo, convierte JSON, valida campo por campo y arma headers. Cada ruta nueva repetiría ese trabajo, y cada repetición es una oportunidad de equivocarse.

Un framework resuelve esa parte repetitiva una sola vez. Con FastAPI, el programador declara qué datos espera cada ruta y qué devuelve, y FastAPI se encarga del resto. La etapa 02 reescribe la misma API en 89 líneas, con las mismas rutas y los mismos campos.

2. Concepto

2.1 FastAPI es la aplicación; Uvicorn es el servidor

En la etapa 01, un mismo archivo hacía dos trabajos: escuchar el puerto 8000 y decidir qué responder. Con FastAPI esos trabajos se separan en dos programas (Tabla 1). Uvicorn es el servidor: abre el puerto, recibe los bytes y entrega cada petición a la aplicación. FastAPI es la aplicación: decide qué función atiende cada ruta y arma la respuesta.

Los dos se entienden mediante ASGI (Asynchronous Server Gateway Interface o Interfaz de Pasarela de Servidor Asíncrona), un estándar de Python que define cómo un servidor le pasa una petición a una aplicación. Gracias a ese estándar, Uvicorn podría reemplazarse por otro servidor ASGI sin tocar el código de la API.

2.2 El entorno virtual

Un entorno virtual es una carpeta con su propio intérprete de Python y sus propias librerías. Sirve para que cada proyecto tenga las versiones que necesita sin afectar a los demás ni a la instalación de Windows. Todo el aprendizaje comparte uno, en aprendizaje/.venv. Se crea una vez, se activa en cada terminal nueva y después se instala lo que pide cada etapa: 

python -m venv .venv                       # crea el entorno (una sola vez)
.venv\Scripts\Activate.ps1                 # lo activa en esta terminal: el prompt muestra (.venv)
pip install -r etapas/02_fastapi_basico/requirements.txt

El archivo requirements.txt lista las librerías del proyecto. La línea fastapi[standard] instala FastAPI junto con sus extras habituales, entre ellos Uvicorn y el comando fastapi.

2.3 Arrancar el servidor

El comando fastapi dev main.py busca la variable app en main.py, arranca Uvicorn en http://127.0.0.1:8000 y lo reinicia cada vez que se guarda un archivo. Esa recarga automática es cómoda para desarrollar, pero en producción se usa fastapi run, que no vigila archivos. Por dentro, los dos ejecutan algo equivalente a uvicorn main:app, que significa «la variable app del módulo main».

2.4 Rutas con decoradores

Un decorador es una línea que empieza con @ y modifica o registra la función que tiene debajo. @app.get("/productos") le dice a FastAPI que esa función atiende las peticiones GET a /productos. Al arrancar, FastAPI recorre todos los decoradores y arma una tabla de rutas. Las llaves marcan las partes variables de la ruta: /productos/{producto_id} coincide con /productos/1, con /productos/99 y también con /productos/abc.

2.5 De dónde saca FastAPI cada parámetro

FastAPI lee la firma de la función y decide de qué parte de la petición sale cada parámetro, según las reglas de la Tabla 2. Después convierte cada valor al tipo anotado. Si no puede, responde 422 sin ejecutar la función.

2.6 Pydantic: la forma de los datos

Pydantic es la librería que valida datos a partir de clases. Una clase que hereda de BaseModel declara los campos y sus tipos, y Field agrega restricciones. En ProductoIn, el nombre tiene entre 1 y 80 caracteres, la unidad solo puede ser "kg" o "unidad" (eso expresa Literal) y el precio es un Decimal mayor que cero con hasta 2 decimales. Esas tres líneas reemplazan a la función validar_producto de la etapa 01.

Cuando los datos no cumplen el schema, FastAPI responde 422 con una lista de errores. Cada error indica dónde está el problema (loc, por ejemplo ["body", "precio"]), qué regla falló (type), un mensaje (msg) y el valor recibido (input).

2.7 La respuesta

La función devuelve objetos de Python y FastAPI los convierte a JSON. La anotación de retorno (-> ProductoOut) funciona como modelo de respuesta: FastAPI valida lo que sale y descarta cualquier campo que no figure en él. En el módulo 06 eso evita que el hash de una contraseña llegue al navegador por accidente.

El código de éxito se fija en el decorador con status_code=201. Para responder con un error, la función lanza HTTPException. No es una falla del programa: es la forma de pedirle a FastAPI que corte ahí y responda con ese código y ese detail.

2.8 Documentación automática

FastAPI genera la descripción completa de la API en formato OpenAPI (OpenAPI Specification o Especificación OpenAPI), un estándar para describir rutas, parámetros y respuestas. Esa descripción está en /openapi.json, y /docs la muestra como una página interactiva donde se puede probar cada ruta con el botón «Try it out». Como sale del código, la documentación no queda desactualizada.

¿def o async def? FastAPI acepta los dos. Una función def se ejecuta en un hilo aparte, así que no bloquea a las demás peticiones. Las etapas usan def porque SQLAlchemy, en el módulo 05, se usa de forma sincrónica. async def conviene cuando la función espera operaciones asíncronas con await.

3. Código mínimo

El schema reemplaza la validación manual:

class ProductoIn(BaseModel):
    nombre: str = Field(min_length=1, max_length=80)
    unidad: Literal["kg", "unidad"]
    precio: Decimal = Field(gt=0, max_digits=10, decimal_places=2)

class ProductoOut(ProductoIn):
    id: int

Cada ruta es una función con un decorador. Los parámetros y el tipo de retorno son todo lo que FastAPI necesita:

@app.get("/productos/{producto_id}")
def obtener_producto(producto_id: int) -> ProductoOut:
    if producto_id not in productos:
        raise HTTPException(status_code=404, detail="Producto no encontrado")
    return productos[producto_id]

6. Errores comunes

«La ejecución de scripts está deshabilitada» al activar el entorno.

Windows PowerShell bloquea por defecto los scripts como Activate.ps1. Se puede habilitar para el usuario con Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, o evitar la activación y usar la ruta completa: .venv\Scripts\fastapi.exe dev main.py.

El puerto 8000 está ocupado.

Si el servidor de la etapa 01 sigue abierto en otra terminal, Uvicorn no puede usar el puerto y muestra un error de dirección en uso. Se cierra el otro servidor con Ctrl+C o se elige otro puerto con fastapi dev main.py --port 8001.

Olvidar la anotación de tipo.

Un parámetro sin tipo se recibe como texto y no se valida. def obtener_producto(producto_id) recibiría "1" en lugar de 1, y la búsqueda en el diccionario fallaría con un 404 engañoso.

Esperar que los datos sobrevivan a la recarga.

fastapi dev reinicia el proceso al guardar un archivo, y con él se reinicia el diccionario. No es un error de FastAPI: los datos en memoria duran lo que dura el proceso.

Llamar fastapi.py a un archivo propio.

Python buscaría from fastapi import FastAPI en ese archivo en lugar de la librería, y fallaría con un error de importación difícil de entender.

7. Ejercicios

1. Levantá la etapa 02 y ejecutá python ../01_http/cliente.py. ¿Qué caso responde distinto que en la etapa 01? ¿Qué información extra trae la respuesta?

Ver respuesta

El caso 4 responde 422 en lugar de 400. Cada error de la lista trae el campo (loc), el tipo de regla que falló, un mensaje, el valor recibido y, a veces, el límite (ctx, por ejemplo {"gt": 0}). La etapa 01 solo devolvía textos.

2. Agregá la ruta GET /productos/buscar?q=queso que devuelva los productos cuyo nombre contenga q. Escribila después de obtener_producto y probala. ¿Qué responde y por qué? ¿Cómo se arregla?

Ver respuesta

Responde 422: FastAPI prueba las rutas en el orden en que se declararon, y /productos/buscar coincide primero con /productos/{producto_id}. Como "buscar" no es un entero, falla la validación. Se arregla declarando /productos/buscar antes, o mejor, agregando el parámetro q a GET /productos, que es la forma REST de filtrar una colección.

3. En /docs, creá un producto con precio "12.345". ¿Qué pasa y qué línea de main.py lo decide?

Ver respuesta

Responde 422 porque el precio tiene 3 decimales. Lo decide decimal_places=2 en el Field del precio, en la línea 30.

4. Cambiá producto_id: int por producto_id: str en obtener_producto y pedí /productos/1. ¿Qué responde ahora y por qué?

Ver respuesta

Responde 404: el id llega como el texto "1" y las claves del diccionario son enteros, así que "1" not in productos es verdadero. El tipo anotado no es decorativo: FastAPI convierte el valor según ese tipo.

5. Implementá PATCH /productos/{producto_id} para cambiar solo algunos campos. Pista: un schema ProductoPatch con todos los campos opcionales y datos.model_dump(exclude_unset=True).

Ver respuesta 
class ProductoPatch(BaseModel):
    nombre: str | None = Field(default=None, min_length=1, max_length=80)
    unidad: Literal["kg", "unidad"] | None = None
    precio: Decimal | None = Field(default=None, gt=0, max_digits=10, decimal_places=2)

@app.patch("/productos/{producto_id}")
def modificar_producto(producto_id: int, datos: ProductoPatch) -> ProductoOut:
    if producto_id not in productos:
        raise HTTPException(status_code=404, detail="Producto no encontrado")
    cambios = datos.model_dump(exclude_unset=True)   # solo los campos que se enviaron
    productos[producto_id] = productos[producto_id].model_copy(update=cambios)
    return productos[producto_id]
